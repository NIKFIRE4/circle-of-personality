# Архитектурные решения

## Границы системы

Next.js обслуживает React UI и same-origin API. PostgreSQL — единственный внутренний источник истины. GigaAM изолирован в отдельном Python-процессе, потому что модель тяжёлая, требует FFmpeg/Torch и имеет другую модель масштабирования. Опциональный LLM вызывается только Route Handler-ом: API key не передаётся в браузер, а ответ считается недоверенным до Zod- и доменной валидации. Внешние iCal/ICS-ленты загружаются только сервером; после сохранения их URL не возвращаются в браузер.

## Основные потоки

### Авторизация

После проверки bcrypt-хэша API генерирует криптографически случайный session token. В `HttpOnly + SameSite=Lax` cookie находится исходный token, в `Session.tokenHash` — SHA-256 digest. Logout отзывает server session. Mutating API проверяет same-origin `Origin`/`Host`.

### Календарь и колесо

`Event` хранит время и статус, `BalanceCategory` — сферу и недельную цель. Индекс сферы за текущую неделю:

```text
min(100, added task minutes / targetMinutesPerWeek × 100)
```

Общий индекс — среднее сфер с заданной недельной целью. Отменённые и целодневные события не участвуют в расчёте минут: целодневная задача не должна автоматически добавлять 24 часа. Границы событий обрезаются границами локальной недели пользователя, а каждый процент ограничен диапазоном 0–100.

### Умная текстовая или голосовая задача

1. Пользователь вводит одну фразу или Browser MediaRecorder записывает до 20 секунд речи.
2. Next API проверяет сессию, same-origin и частоту запросов; для голоса также проверяется размер upload.
3. FastAPI повторно ограничивает request/file, проверяет длительность через ffprobe и сериализует STT inference.
4. GigaAM возвращает только transcript; временный файл удаляется.
5. Общий task interpreter передаёт LLM фиксированные `now`, IANA timezone и список активных категорий. OpenRouter использует JSON Object Mode, GigaChat — strict JSON Schema.
6. Zod и серверные проверки отклоняют лишние поля, неизвестную категорию, невозможное локальное время и некорректный диапазон. При отсутствии ключа, timeout, `429`, `5xx` или неверном JSON используется локальный русский parser.
7. UI показывает title/start/end/category и всегда требует подтверждение.
8. Transaction создаёт Event; для голоса дополнительно переводит VoiceCommand `PARSED → APPLIED`, затем пишет AuditLog и Outbox. Печатный preview до подтверждения в БД не хранится.

### Внешние календари по iCal/ICS

Основной сценарий не использует OAuth и не требует от пользователя API-ключей. Для Google пользователь копирует **Secret address in iCal format**, для Apple/iCloud включает **Public Calendar** и копирует `webcal://`-ссылку. Интерфейс передаёт URL по same-origin HTTPS один раз; дальше ленту получает и разбирает сервер.

iCal URL является bearer-секретом. Он хранится зашифрованным AES-256-GCM с ключом `CALENDAR_FEED_ENCRYPTION_KEY`; если новый ключ не задан, используется legacy fallback `GOOGLE_TOKEN_ENCRYPTION_KEY`. Открытый URL не возвращается клиенту и не записывается в аудит или прикладные логи. `webcal://` нормализуется для серверной загрузки по HTTPS.

Обновление запускается автоматически при открытии страницы календаря и по кнопке пользователя. Сервер загружает ICS, использует доступные `ETag`/`Last-Modified`, разбирает события и обновляет их в PostgreSQL. Ошибка отдельной ленты не удаляет уже импортированные события и не мешает открыть локальный календарь.

MVP импортирует Google/Apple → PostgreSQL только для чтения. Заголовок, время и удаление внешнего события управляются в исходном календаре; категория и локальный статус остаются данными КОНТУР.КОСТРОВ. Существующий Google OAuth backend сохраняется как legacy/optional и не нужен для iCal-подписки. Его развитие оправдано позже для write access и двусторонней синхронизации.

## Модель данных

- `User`, `Session`;
- `BalanceCategory`, `Goal`, `Event`;
- `CalendarConnection` — источник, отображаемое имя, зашифрованный URL ленты, метаданные условной загрузки и время последнего обновления;
- `GoogleCalendarConfig` — legacy-конфигурация необязательного Google OAuth;
- `VoiceCommand`;
- `AuditLog`, `Outbox`.

Все пользовательские запросы фильтруются по `userId`. Внешний id события уникален внутри `CalendarConnection`. VoiceCommand имеет уникальную связь с Event, а атомарный conditional update не позволяет применить команду дважды.

## Деградация

- без ключа шифрования нельзя добавить новую iCal/ICS-подписку, но локальный календарь продолжает работать;
- без speech service доступно ручное создание событий;
- без AI key или при исчерпании бесплатной квоты текстовый/голосовой ввод использует локальный parser;
- при сбое Google/Apple import локальные и уже импортированные данные не удаляются;
- `prefers-reduced-motion` отключает декоративные анимации;
- production UI не зависит от внешнего 3D-ассета: фигура собирается из Three.js primitives.
